## Prohibited Dependencies

### `jszip@3.10.1`  **REPLACE IMMEDIATELY**

| Field | Value |
|-------|-------|
| Declared SPDX | `(MIT OR GPL-3.0-or-later)` |
| Actual license text | Dual: MIT **and** full GPLv3 text in the same `LICENSE.markdown` |
| Blue Oak rating | Lead (dual with copyleft arm) |
| Verdict | **PROHIBITED** |

**Why the SPDX field is not enough here:**  
The SPDX expression `MIT OR GPL-3.0-or-later` means the *recipient* chooses which license applies. A naïve check that sees "MIT" and moves on would miss this. Reading the actual license file reveals the full GPLv3 text embedded alongside the MIT text - the package is explicitly dual-licensed and the GPL arm is live.

**Business risk:**  
GPL's copyleft clause requires any work that is a "combined work" or links against a GPL library to be distributed under GPL as well, with source code. For a closed-source SaaS this is incompatible: even if you never distribute binaries, the risk of a copyright claim or a forced open-source disclosure of convo-hub-api's source is material. Legal exposure scales with how central the library is to your product.

**What to do:**  
JSZip is used for ZIP file creation/reading. Permissively-licensed alternatives:

| Alternative | License | Notes |
|-------------|---------|-------|
| `fflate` | MIT | Faster, smaller, actively maintained |
| `archiver` | MIT | Stream-based, good for server-side ZIP generation |
| `adm-zip` | MIT | Drop-in for reading/writing ZIPs |

Replace `jszip` with `fflate` (MIT) in `package.json`, audit usages, and re-run this check.

## CI Check Design

### How it works (three required criteria)

**Criterion 1  GPL/AGPL/SSPL/BUSL blocks the PR:**  
`scripts/license-check.js` exits with code `1` whenever any of these identifiers appear in the SPDX expression *or* their full name appears in the license file text. GitHub Actions treats a non-zero exit as a failed required check, which blocks merge.

**Criterion 2  MIT/Apache-2.0/ISC passes silently:**  
These identifiers are in the `ACCEPTED_SPDX` allowlist. The script emits a single `ACCEPTED` line and exits `0`. No label is applied, no comment is posted.

**Criterion 3  Dual/unrated/restrictive-clause gets label + comment, does not block:**  
The workflow's `license_gate` step can exit `0` even when review packages are present (review  prohibited). Separate `if: steps.license_gate.outputs.review_needed == 'true'` steps apply the `license-review-needed` label and post a comment listing each package and reason. The PR remains mergeable but the label signals that legal sign-off is outstanding.

### Files to commit

```
scripts/license-check.js           the check (run locally or in CI)
.github/workflows/license-gate.yml  GitHub Actions wiring
```

### Running locally before pushing

### Extending for vendor packages

Add this block inside `main()` after the npm tree scan to cover the `./vendor/` directory:

```js
// Scan vendor directories
const vendorDir = path.join(process.cwd(), "vendor");
if (fs.existsSync(vendorDir)) {
  for (const pkg of fs.readdirSync(vendorDir)) {
    const licFile = ["LICENSE", "LICENSE.md", "LICENSE.txt"]
      .map(f => path.join(vendorDir, pkg, f))
      .find(fs.existsSync);
    const text = licFile ? fs.readFileSync(licFile, "utf8") : "";
    // Apply the same PROHIBITED_TEXT_PATTERNS scan
    for (const pattern of PROHIBITED_TEXT_PATTERNS) {
      if (pattern.test(text)) {
        prohibited.push({ package: `vendor/${pkg}`, verdict: "PROHIBITED",
          reason: `Vendor license text matches: ${pattern}`, declared: "unknown" });
      }
    }
    if (!licFile) {
      review.push({ package: `vendor/${pkg}`, verdict: "REVIEW",
        reason: "No LICENSE file found in vendor directory", declared: "unknown" });
    }
  }
}
```
